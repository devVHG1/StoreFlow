# StoreFlow: готовність до демонстрації

Стан на 30.10.2026. Проєкт готовий як навчальний backend із вебінтерфейсом і як портфоліо.
Для зовнішнього магазину залишаються окремі роботи з експлуатації та комерційних процесів.

## Завершено

- 4 шари застосунку, PostgreSQL, EF Core та відтворювані міграції.
- Categories, Products, Users, JWT і ролі; перевірки власника замовлення на сервері.
- Валідація, контроль довжини полів, нормалізація й унікальність email.
- Однакові безпечні відповіді помилок; контроль конфліктів і версії товару.
- Замовлення з резервуванням, повторними безпечними запитами створення, статусами, скасуванням і поверненням залишків.
- Автоматичне закінчення резерву, журнал складу та історія статусів.
- Історичні ціни й назви позицій, захищені правилами PostgreSQL.
- Пошук, фільтри, сортування й сторінки товарів; серверні сторінки та фільтри замовлень.
- Синій магазин покупця й панель менеджера; кошик, власні замовлення, обробка замовлень.
- Docker Compose, автоматична перевірка збірки, тестів, залежностей і контейнерів у GitHub Actions.
- Резервні копії локальної й контейнерної бази з реальним ізольованим відновленням.

## Перевірено

- Release-збірка без помилок і попереджень.
- 51 unit-тест, 8 перевірок JavaScript та 1224 інтеграційні перевірки через API й PostgreSQL.
  Інтеграційне число означає окремі твердження, а не 1224 незалежні сценарії.
- У браузері: магазин із 21 демонстраційним замовленням, усі 3 сторінки;
  панель із 2 сторінками та фільтр 6 скасованих замовлень. Дані в окремій тимчасовій базі.
- У Linux CI: Docker-стек, міграції, сторінки, стан готовності;
  архів бази відновлено, відбитки даних збіглися, тимчасову базу прибрано.
- Відкриті конфігурації перевірені на паролі та ключі. Секрети й копії виключені з Git.

## Як показати проєкт

1. Запустити за README локально або через scripts/Start-Docker.ps1.
2. Відкрити магазин, знайти товар, додати в кошик, увійти й оформити замовлення.
3. Відкрити власні замовлення, деталі й історію; показати скасування та повернення товару.
4. У панелі менеджера показати товари, зміну залишку з причиною, фільтри та статуси замовлень.
5. У Swagger показати ролі, валідацію й конфлікт застарілої версії товару.
6. На GitHub показати зелений CI, структуру шарів, міграції та тести.

Не використовуйте демонстраційні тестові паролі як реальні облікові дані.
Для тестування API створення замовлення передайте новий Idempotency-Key; для повтору того самого запиту збережіть ключ.

## Відомі обмеження

- На цьому Windows-комп’ютері Docker Desktop поки не підтвердив готовності рушія.
  Це відкритий пункт локального середовища; успішний Linux CI його не закриває.
  До усунення проблеми користуйтеся локальним запуском .NET і PostgreSQL із README.
- Немає відновлення забутого пароля та підтвердження email через поштового провайдера.
- Немає оплати, доставки, повернень оплаченого товару й платіжних вебхуків.
- Немає зовнішнього розгортання з доменом, HTTPS, моніторингом та сповіщеннями про збої.
- Обмеження частоти входу зберігається в пам’яті одного процесу; для кількох екземплярів потрібне спільне сховище.
- Копії перевіряються вручну або в CI; розклад, шифроване зовнішнє сховище й політика зберігання ще не налаштовані.
- Каталог без фото товарів, валюти й правил доставки. Панель не охоплює всі адміністративні дії API.
- Перевірки навантаження та незалежний аудит безпеки не виконувались.

Ці обмеження зафіксовані як наступний етап і не приховуються за формулюванням «готовий до production».

## Зміна контракту Orders

GET /api/orders тепер повертає PagedResult замість масиву. Магазин, панель, Swagger і тести оновлені.
Інші зовнішні клієнти повинні читати items. Доступні page, pageSize (1–100), status і userId.

Мобільну сторінку замовлень перевірено на ширині 390 px: горизонтального прокручування немає. Статичні ресурси мають версію, щоб оновлення контракту не залишало в браузері старий JavaScript.
