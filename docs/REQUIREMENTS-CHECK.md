# Перевірка вимог StoreFlow — 30.10.2026

| Вимога | Поточний стан і місце реалізації |
|---|---|
| Валідація Product, Category, User, Order | DataAnnotations, власні валідатори й перевірки сервісів; API повертає помилки полів |
| Ціна > 0, залишок >= 0, email, обов’язкові поля | Реалізовано; перевіряється сценаріями ValidationSuite |
| Глобальні 400 / 401 / 403 / 404 / 500 | ExceptionMiddleware, StatusCodePages та відповіді валідації; без внутрішніх exception у відповіді |
| Перевірка і списання залишків, TotalAmount | OrderService та транзакції OrderRepository; поточна ціна фіксується в позиції |
| Статуси, скасування, власні замовлення | Реалізовано; право власності перевіряється сервером, скасування повертає залишок |
| Історія статусів | GET /api/orders/{id}/history, журнал у PostgreSQL |
| Пошук / фільтри / сортування / сторінки Products | ProductQuery, ProductService, CatalogRepository; SearchSuite |
| Unit та integration tests | 49 модульних тестів, 1160 інтеграційних перевірок і 4 перевірки інтерфейсу |
| Dockerfile, Compose, API + PostgreSQL | Реалізовано; scripts/Start-Docker.ps1 створює секрети за потреби, запускає стек і перевіряє готовність |

30.10.2026 єдиний локальний прогін `pwsh -NoProfile -File scripts/Run-IntegrationTests.ps1` завершився успішно:
4 перевірки інтерфейсу, Release build без помилок і попереджень, 49 unit-тестів та 1160 інтеграційних перевірок без помилок.
Інтеграційні сценарії використовували окрему тимчасову PostgreSQL, яка видаляється після завершення.

Локальний Docker Desktop сьогодні не підтвердив готовність рушія. Скрипт завершив очікування за таймаутом;
наявні томи й секрети не видалялися. Та сама команда запуску перевіряється job `container` у GitHub Actions на Linux.
Актуальний результат дивіться у вкладці Actions репозиторію.

Цей список стосується запитаних функцій. Оплата, доставка, зовнішнє розгортання й інші описані в README обмеження залишаються окремою роботою.
